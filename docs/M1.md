# M1.1 - Architecture-Aware Browse and Search

## Scope

M1 adds the two remaining read-only Aminet discovery modes:

- **Browse** follows Aminet's category hierarchy from the public tree.
- **Search** queries Aminet's public simple search interface.
- Both modes use the existing lightbar selector and README reader.
- Browse and Search can restrict package results to configured architectures.

## Endpoints

Browse starts at:

```text
GET https://aminet.net/tree
GET https://aminet.net/tree?path=<category>
```

Leaf package listings use the category path directly:

```text
GET https://aminet.net/<category-path>
```

Unfiltered Search uses the public simple form endpoint:

```text
GET https://aminet.net/search?query=<term>
GET https://aminet.net/search?query=<term>&page=<number>
```

When `ARCHITECTURE_FILTER` is not `None`, Aminet's verified Advanced Search
form is used instead:

```text
GET https://aminet.net/search?type=advanced&name=<term>&q_desc=OR&desc=<term>&q_arch=AND&arch[]=<architecture>...
GET https://aminet.net/search?type=advanced&path[]=<category>&q_arch=AND&arch[]=<architecture>...
```

The live Aminet interface exposes architecture filtering through repeated
`arch[]` fields. Architecture subdomains shown in the page header are views,
not a reliable package filter, so AminetDoor does not use them for filtering.

Queries are encoded with `urllib.parse.urlencode()` and limited to 60
characters. Browse and Search responses are bounded and parsed with Python's
standard-library `html.parser.HTMLParser`; no HTML parsing dependency is
required.

## Live Format Notes

The live root Browse page uses relative `tree?path=biz` links. The live
`tree?path=game` page uses direct relative child links such as
`game/shoot` rather than another `tree?path=` link. Leaf package listings are
served at `/game/shoot` and contain `pkg_row` table rows with a file link such
as `/game/shoot/BOOM_AGA.lha` and a package link such as
`/package/game/shoot/BOOM_AGA`. The README link is
`/game/shoot/BOOM_AGA.readme`.

The Search form is `GET /search` with the `query` parameter and no required
hidden fields. Results are in the `start_listing` table, with the same
package/detail link pattern and a public `page` parameter for later results.
The parser accepts both Browse's category list and the package result table;
unrelated navigation links are ignored.

## Controls

Browse uses Up/Down and Enter, with `B` for one level back, `R` for root, and
`ESC`/`Q` to leave Browse. The category tree remains complete; filtering only
changes package listings inside a category. Search uses Up/Down and Enter,
`S` for a new search, and `ESC`/`Q` to leave Search. Selected packages open
the existing paged `.readme` reader.

## Architecture Configuration

The default in `aminetdoor.mpy` is:

```python
ARCHITECTURE_FILTER = ("m68k-amigaos", "generic")
```

It targets classic 68k AmigaOS while retaining architecture-independent
content. Set it to `None` for all architectures. Invalid entries are ignored;
if no valid entries remain, AminetDoor safely uses the unfiltered view. Recent
RSS uploads remain unfiltered because the feed does not expose reliable
architecture metadata.

## Out Of Scope

M1 does not add downloads, uploads, login/cookies, caching, favorites,
ratings, statistics, screenshots, architecture persistence, mirrors, or FTP.
