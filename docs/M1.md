# M1.1 - Architecture-Aware Browse and Search

## Scope

M1 adds the two remaining read-only Aminet discovery modes:

- **Browse** follows Aminet's category hierarchy from the public tree.
- **Search** queries Aminet's public simple search interface.
- Both modes use the existing lightbar selector and README reader.
- Browse and Search can restrict package results to configured architectures.

## Endpoints

Browse category navigation starts from the inline catalog mirroring Aminet's
public Browse tree:

```text
local catalog root and child categories
```

Leaf package listings use the category path directly:

```text
GET https://aminet.net/<category-path>
```

Unfiltered Search uses the public simple form endpoint:

```text
GET https://aminet.net/search?query=<term>
GET https://aminet.net/search?query=<term>&page=<number>
```

When `ARCHITECTURE_FILTER` is not `None`, Aminet's verified Advanced Search
form is used instead:

```text
GET https://aminet.net/search?type=advanced&name=<term>&q_desc=OR&desc=<term>&q_arch=AND&arch[]=<architecture>...
GET https://aminet.net/search?type=advanced&path[]=<category>&q_arch=AND&arch[]=<architecture>...
```

The live Aminet interface exposes architecture filtering through repeated
`arch[]` fields. Architecture subdomains shown in the page header are views,
not a reliable package filter, so AminetDoor does not use them for filtering.

The catalog is intentional resilience infrastructure, not an offline Aminet
mirror. It contains category names only; package listings remain live. When
Aminet changes its category structure, the inline catalog should be verified
against the public Browse tree and updated deliberately.

Queries are encoded with `urllib.parse.urlencode()` and limited to 60
characters. Browse and Search responses are bounded and parsed with Python's
standard-library `html.parser.HTMLParser`; no HTML parsing dependency is
required.

## Live Format Notes

The catalog was derived from Aminet's public root and child category paths.
Leaf package responses contain `pkg_row` table rows with a file link such as
`/game/shoot/BOOM_AGA.lha` and a package link such as
`/package/game/shoot/BOOM_AGA`. The README link is
`/game/shoot/BOOM_AGA.readme`.

The Search form is `GET /search` with the `query` parameter and no required
hidden fields. Results are in the `start_listing` table, with the same
package/detail link pattern and a public `page` parameter for later results.
The parser accepts both Browse's category list and the package result table;
unrelated navigation links are ignored.

## Controls

Browse uses Up/Down and Enter, with `B` for one level back, `R` for root,
`J` to jump directly to a validated category path, and `ESC`/`Q` to leave
Browse. For example, `game/shoot`, `comm/net`, and `dev/cross` are accepted;
the jump uses the same architecture filtering and package reader as ordinary
Browse. The category tree remains complete; filtering only changes package
listings inside a category. Search uses Up/Down and Enter, `S` for a new
search, and `ESC`/`Q` to leave Search. Selected packages open the existing
paged `.readme` reader.

## M1.5 Package of the Day

The main menu's `P` action selects one deterministic package from the current
Recent feed using the local calendar date and canonical package path. All
callers see the same spotlight for the same day. `Enter` opens the existing
README reader, `R` cycles to another already-fetched Recent candidate, and
`ESC`/`Q` returns to the main menu. The candidate pool is unfiltered, just like
Recent.

## M1.6 Favorites

Favorites use Mystic's supported `bbs.getuserid()` value as a stable per-user
identity. JSON files are stored under `USER_DATA_DIR/favorites` (default
`data/users`, relative to Mystic's process working directory) using a hashed
user-ID filename. `F` toggles a package bookmark in package contexts; `F` from
the main menu opens the Favorites lightbar, where `D` deletes and Enter opens
the existing cached README reader. Favorites are local BBS data only, are not
sent to Aminet, and storage failures do not disable core AminetDoor features.
The configured default is `USER_DATA_DIR = "data/users"`; relative paths use
Mystic's process working directory and absolute SysOp paths are supported.

## Architecture Configuration

The default in `aminetdoor.mpy` is:

```python
ARCHITECTURE_FILTER = ("m68k-amigaos", "generic")
```

It targets classic 68k AmigaOS while retaining architecture-independent
content. Set it to `None` for all architectures. Invalid entries are ignored;
if no valid entries remain, AminetDoor safely uses the unfiltered view. Recent
RSS uploads remain unfiltered because the feed does not expose reliable
architecture metadata.

## M1.2 README Cache

Only fetched plain-text package `.readme` content is cached. The cache defaults
to `cache/readme` relative to Mystic's process working directory, with a
24-hour TTL. SysOps should set `CACHE_DIR` to an absolute path when that
working directory is not stable:

```python
CACHE_ENABLED = True
CACHE_DIR = "cache/readme"
CACHE_MAX_AGE_SECONDS = 86400
```

Entries use a SHA-256 key derived from the canonical package path and are stored
as JSON. Writes use a same-directory temporary file and atomic replacement.
Corrupt or mismatched entries are treated as misses. If a stale entry exists
and a refresh fails at the network layer, the stale README remains available.
Cache initialization, lookup, and write failures bypass caching and continue
with the normal Aminet fetch.
Recent RSS, Browse/Search HTML, archives, and screenshots are not cached.
Cached package content remains subject to its original authors' copyright and
licensing terms.

## Out Of Scope

M1.2 does not add downloads, uploads, login/cookies, favorites, ratings,
statistics, screenshots, architecture persistence, mirrors, or FTP.
